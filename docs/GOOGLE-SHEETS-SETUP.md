# Google 登入與雲端同步設定（個人 Google 帳號＋Google 試算表）

v6.1 起，**老師必須先用 Google 帳號登入才能進入班級經營動力站**（方案 A）。每個 Google 帳號在同一台電腦上有各自的資料區，彼此看不到。雲端同步（Google 試算表）仍是選用功能：不設定的話，資料只存在這台電腦的瀏覽器（IndexedDB）。

登入與同步使用同一個 OAuth Client ID，但它們是兩個不同的步驟：
- **登入（身分驗證）**：確認你是誰。系統只取得帳號識別碼、名稱與 Email，用來分開資料。
- **試算表授權**：允許 App 讀寫「它自己建立的」試算表。授權的帳號必須是登入中的同一個帳號，否則系統會拒絕。

> ⚠️ 使用前請先確認學校的個人資料規定：試算表會存放學生座號、姓名、加扣分與作業紀錄。若學校要求使用學校核准的 Google Workspace 帳號，請用該帳號建立下列設定。

## 一、只需要做一次：建立 OAuth Client ID（約 10 分鐘，由管理者或老師本人操作）
> 這一步會建立真實的 Google Cloud 資源。在本專案的開發流程中，只有使用者另外核准後才進行。

1. 用你要存放資料的 Google 帳號登入 <https://console.cloud.google.com/>，建立一個新專案（例如「班級動力站」）。
2. 到「API 和服務 → 程式庫」，搜尋 **Google Sheets API**，按「啟用」。
3. 「API 和服務 → OAuth 同意畫面」：
   - 使用者類型：個人帳號選「外部」；學校 Workspace 帳號可以選「內部」。
   - 填寫應用程式名稱與支援電子郵件。
   - 範圍（Scopes）加入：
     - `openid`、`.../auth/userinfo.email`、`.../auth/userinfo.profile`：登入用，屬於非敏感範圍。
     - `https://www.googleapis.com/auth/drive.file`：只能存取本 App 建立，或你用本 App 開啟的檔案，看不到你雲端硬碟的其他檔案。
   - 若選「外部」且還在「測試」狀態：在「測試使用者」加入每一位要登入的老師的 Gmail。
     **沒加入的帳號仍可能「登入」成功，但按「連接 Google 試算表授權」時會被 Google 擋下（403 access_denied）。**
4. 「API 和服務 → 憑證 → 建立憑證 → OAuth 用戶端 ID」：
   - 應用程式類型：**網頁應用程式**
   - 已授權的 JavaScript 來源：填你開啟 App 的網址的「來源」，例如：
     - 正式網站：`https://yongliancai.github.io`
     - 在自己電腦測試：`http://localhost:8765`（以及 `http://127.0.0.1:8765`）
   - 不需要填「重新導向 URI」（登入與授權都使用彈出視窗）。
5. 建立後複製 **用戶端 ID**，格式像 `1234567890-abc123.apps.googleusercontent.com`。
   - **完全不需要用戶端密鑰（client secret）**，請不要貼到任何地方，也不要放進 GitHub。

## 二、把 Client ID 放進 App（擇一）
- **部署時設定（建議）**：管理者在 `src/config.js` 填入 `GOOGLE_CLIENT_ID`。Client ID 是公開識別碼，不是密碼，但修改正式網站需要使用者另外核准。
- **在這台電腦設定**：如果 `src/config.js` 沒填，登入畫面會出現「OAuth Client ID」欄位。貼上後按「儲存」即可，只會存在這台電腦。

## 三、登入
1. 開啟 App，按「使用 Google 帳號登入」，選擇你的帳號。
2. 驗證通過後才會進入。右上角會顯示目前的帳號（Email）。
3. 第一次在這台電腦登入時，如果這台電腦有「登入功能上線前」的舊資料，會出現黃色提示。按「預覽並選擇是否匯入」，勾選屬於你的班級即可（見使用說明）。

## 四、第一台電腦：建立試算表
1. 按右上的「☁️ 雲端狀態」，再按「🔐 連接 Google 試算表授權」，在 Google 視窗選擇**同一個帳號**並同意。
2. 按「＋ 建立新的試算表」。完成後可以按「開啟 Google 試算表 ↗」查看。

## 五、其他電腦
1. 用同一個 Google 帳號登入，然後連接試算表授權。
2. 在「試算表」欄位貼上第一台電腦那份試算表的網址，按「使用這份」。系統會先確認這個帳號能開啟它，再自動合併資料。
   - 如果是別的帳號建立、沒有分享給你的試算表，系統會拒絕，也不會改用其他試算表。

## 六、平常使用
- 每次修改先存在本機，幾秒後自動同步；離線時照常使用，恢復網路自動補上。
- Google 授權大約 1 小時過期（瀏覽器 token 模式不保存長期權杖），狀態會顯示「需要重新連線」，按一下「重新連線」即可，期間的修改都保留。
- 兩台電腦改到「同一筆」資料時，不會自動蓋掉：狀態顯示「⚠ 同步衝突」，在設定視窗選「用這台電腦的」或「用雲端的」。
- 作業紀錄是逐筆新增的事件，兩台同時登記同一格時，會在作業畫面標示「⚠ 衝突」讓你選。
- 試算表 A–G 欄是同步用的，請不要手動修改；H 欄之後是給你閱讀、篩選用的。刪除只會標記 `deleted=1`，原資料仍保留在那一列。

## 七、隱私與停用
- 試算表建立在你的雲端硬碟，預設不分享給任何人。請不要用「知道連結的人都能檢視」分享。
- App 只在記憶體保存 Google access token，不寫入 localStorage / IndexedDB，也不會出現在試算表裡。
- 停用：設定視窗按「中斷同步」。本機與試算表的資料都保留；不需要時可自行到雲端硬碟刪除該試算表。

## 八、從舊版 Firebase 搬資料
- v6 不會讀取、修改或刪除舊的 Firebase/Firestore 資料。
- 需要舊雲端資料時：用 v5.1 版本（GitHub `main` 舊版本，commit `44879bb`）開啟 → 「匯出備份」→ 在 v6「載入備份」。導入前 App 會先自動下載目前資料的備份。
- 舊 Firebase 專案要不要停用或刪除，由你自行決定；本專案不會替你操作。

## 九、限制（請知悉）
- Google 試算表不是交易型資料庫：設計為「一位老師、多台裝置」使用。若多位老師同時大量編輯，仍可能需要人工處理衝突；不保證完全強一致。
- Google Sheets API 每位使用者每分鐘讀取約 60 次；App 每次同步約 3–15 次請求，並在 429/5xx 時自動退避重試（5 秒、15 秒、45 秒…最多 5 分鐘）。
- 單一試算表上限約 1000 萬個儲存格；一個 28 人班級一學年的紀錄遠低於此上限。

## 疑難排解
| 現象 | 原因與處理 |
|---|---|
| 登入畫面顯示「尚未設定 Google 登入」 | `src/config.js` 沒填 Client ID，而且這台電腦也還沒輸入；請貼上用戶端 ID。 |
| 「登入驗證失敗」 | 憑證不是發給本 App、已過期，或電腦時間不正確；請校正時間後重新登入。 |
| 「目前沒有網路」 | 登入需要連線到 Google；資料仍保存在這台電腦。 |
| 「授權的 Google 帳號與目前登入的帳號不同」 | 在 Google 試算表授權視窗請選登入中的同一個帳號。 |
| 「無法存取這份試算表」 | 試算表是別的帳號建立的，或沒有分享給你；請用建立它的帳號登入。 |
| 「OAuth Client ID 格式不正確」 | 貼到的是密鑰或網址；請貼「用戶端 ID」。 |
| Google 視窗顯示 `origin_mismatch` | 第一節第 4 步的「已授權的 JavaScript 來源」沒有包含目前網址的來源。 |
| 試算表授權視窗顯示「已封鎖存取權：…未完成 Google 驗證程序」、`403 access_denied`；App 顯示「授權視窗已關閉…」 | OAuth 同意畫面仍是「測試」狀態，而這個帳號不在「測試使用者」名單。**登入只用基本範圍，可能照樣成功，但試算表授權（`drive.file`）會被擋。** 到 Google Cloud →「Google 驗證平台／OAuth 同意畫面 → 目標對象（Audience）→ 測試使用者」加入這個 Gmail（2026-11-25 真實驗收時遇到）。 |
| 「尚未啟用 Google Sheets API」（舊版顯示成「沒有這份試算表的存取權限」） | Google 回 `403 SERVICE_DISABLED`：OAuth 用戶端所在的專案沒做第一節第 2 步。到「API 和服務 → 程式庫」搜尋 Google Sheets API 按「啟用」，等幾分鐘再按「建立新的試算表」（2026-11-25 真實驗收時遇到）。 |
| 「已拒絕授權」或「沒有勾選檔案存取權限」 | 在 Google 視窗要勾選允許存取檔案；或你的帳號不在「測試使用者」。 |
| 「找不到試算表」 | 試算表被刪除，或是用不同 Google 帳號建立的；請重新建立或改用正確帳號。 |
| 一直顯示「N 筆待同步」 | 檢查網路與授權（重新連線）；資料不會遺失。 |
