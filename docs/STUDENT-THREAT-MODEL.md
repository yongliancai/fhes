# v6.2 學生系統威脅模型

範圍：`server/`（最小 Node API）、`student.html`（學生頁面）、教師端的發布與帳號管理（`src/ui/student-admin-ui.js`）。日期 2026-11-25。方法：資產 → 攻擊者 → 威脅（STRIDE）→ 對策 → 驗證方式。

## 資產
1. 學生個人資料：姓名、座號、分數、作業狀態（未成年人資料，最高敏感）。
2. 學生帳號密碼（雜湊）與 Session。
3. 教師身分與班級管理權。
4. 照顧紀錄與小組獎勵的公平性。
5. 教師的 Google 試算表與 OAuth token（v6.1 資產，**不能**經過後端）。

## 攻擊者
- A1 好奇或惡作劇的學生（同班、他班），有自己的帳號，會改網址、用開發者工具、重送請求。
- A2 拿到別人密碼或共用裝置上殘留 Session 的人。
- A3 網路上的匿名攻擊者（猜密碼、掃描、CSRF、XSS）。
- A4 另一位老師（有合法教師帳號，但不屬於這個班）。
- A5 伺服器資料外洩（備份檔、資料庫檔被拿走）。

## 威脅與對策

| # | 威脅 | 攻擊者 | 對策 | 驗證（測試） |
|---|---|---|---|---|
| T1 | **身分偽造**：自己簽一個 Google token 或改前端的 sub 冒充老師 | A1 A3 A4 | 後端用 Google JWKS 驗 RS256 簽章、iss、aud/azp、exp、iat≤10 分鐘、nonce；拒絕 `alg:none`；後端不接受任何「前端說我是誰」的欄位 | `server.teacher-auth` 負例：偽簽、錯 aud、錯 iss、過期、太舊、無 sub、alg none、重放 |
| T2 | **ID token 重放**：截到老師的 ID token 拿去換工作階段 | A3 | 同一個 token（SHA-256）只能換一次，保存到過期；Bearer 只在記憶體 | 同 token 第二次 → 401 |
| T3 | **跨學生 IDOR**：學生改參數讀別人資料 | A1 | 學生 API 沒有任何身分參數，全部由 Session 推得；額外欄位一律 400；回應只含本人 DTO | 100 次隨機竄改（query、body、header）都拿不到他人資料 |
| T4 | **跨組／跨班照顧**：照顧別組或別班的動物 | A1 | 後端以 Session 學生的**目前**小組查投影，動物不在其中 → 404 | 跨組、跨班、被撤銷物種、換組後的舊組 → 拒絕 |
| T5 | **他班老師越權**：用自己的合法 Bearer 操作別人的班級 | A4 | 班級以「教師 ID＋本機班級 ID」綁定，所有教師路由先查擁有權，不符回 404 | 教師乙對甲的班級：列帳號、重設、停用、發布 → 404 |
| T6 | **弱密碼／暴力猜測** | A1 A3 | 初始密碼 10 碼高熵（約 49 bits）；新密碼至少 8 碼、不可等於帳號、不可在常見清單、不可單一字元重複或連號；Argon2id（m=19 MiB, t=2）；帳號鎖定＋IP 限流（429）；不存在的帳號也做假驗證 | 錯 5 次鎖定、IP 30 次 → 429、正確密碼在鎖定期間也拒絕 |
| T7 | **帳號列舉**：從錯誤訊息或時間差猜出哪些帳號存在 | A3 | 錯誤訊息一律「帳號或密碼錯誤」；不存在的帳號也跑 Argon2id | 回應內容相同（測試比對） |
| T8 | **學生端全表曝光** | A1 | 後端只存每生 DTO，學生 API 只讀本人那一筆；小組 DTO 不含成員名單 | 外洩掃描：回應中不得出現其他學生姓名、ID、試算表 ID、token |
| T9 | **XSS**：班級名稱、學生姓名、作業標題含 HTML／腳本 | A1 A4 | 學生頁面只用 `textContent` 建 DOM（guardrails 禁止 HTML 字串）；嚴格 CSP（`default-src 'self'`、無 inline script）；API 回 `application/json` 與 `nosniff` | 含 `<img onerror>` 的名稱在畫面上顯示為文字；CSP 標頭測試 |
| T10 | **CSRF**：別的網站讓學生的瀏覽器送照顧或改密碼 | A3 | Cookie `SameSite=Strict`；所有改變狀態的請求必須有 `X-FHES-CSRF`（與 Session 綁定）且 `Origin` 在允許清單；學生 API 不開 CORS | 無標頭、錯標頭、錯 Origin → 403 |
| T11 | **Session 固定／竊取** | A2 A3 | 登入、改密碼都換新的 session id；Cookie `__Host-`、HttpOnly、Secure；伺服器只存 SHA-256；閒置 2 小時、最長 12 小時；登出、改密碼、教師重設或停用 → 全部失效 | 登入前的 cookie 登入後無效；改密碼後舊 Session 401；重設後 401 |
| T12 | **資料投影競爭**：兩台裝置先後發布，舊資料蓋掉新資料 | 教師本人 | `version` 單調遞增，舊版本 409；同版本同內容冪等；整班替換在單一交易內 | 舊版本、同版不同內容、同版同內容、移除學生後舊資料消失 |
| T13 | **多人或重複餵食刷獎勵** | A1 | 每生每日 3 次有效（`slot` 唯一鍵）；`idempotencyKey` 唯一鍵；SQLite 交易；團隊星看參與人數 | 同時 100 次、跨分頁、重送同 key、換組 |
| T14 | **共用裝置** | A2 | 頁面不在 localStorage／IndexedDB 存任何資料；登出鍵明顯；閒置 2 小時自動失效；首次登入強制改密碼 | 掃描瀏覽器儲存空間只有 Cookie |
| T15 | **後端資料外洩** | A5 | 不存明文密碼、不存 session id 原文、不存教師 email／sub 原文；稽核紀錄的 IP 用帶鹽雜湊；備份需加密（部署事項） | 資料庫掃描測試：找不到初始密碼、session id、sub |
| T16 | **教師 token 外洩到後端** | — | 教師端只送 DTO；後端沒有任何接收 Google access token 的欄位；試算表 ID 不在 DTO | 外洩掃描：發布內容不含 `ya29`、試算表 ID、access token |
| T17 | **大量請求耗盡資源** | A3 | 請求大小上限（投影 2 MB、其他 16 KB）；登入限流；Argon2 並行上限 | 超大請求 413 |
| T18 | **照顧影響正式積分** | 設計錯誤 | 照顧表與 XP／分數完全分離；投影建構只讀 v6.1 資料，不讀照顧 | 照顧 100 次後，重新產生的投影與 XP 不變 |

## 剩餘風險（接受或待處理）
- **學生把密碼告訴別人**：系統無法防止；教師可隨時重設。
- **教師帳號被盜**：沿用 Google 帳號安全；後端無法分辨。
- **SQLite 單機**：只適合一所學校的規模（數百名學生）；超過需換資料庫。
- **未在正式 VPS 驗證**：TLS、反向代理、真實 IP（`X-Forwarded-For` 信任設定）、備份都還沒做（需批准）。
- **Argon2 原生模組**：需在 VPS 上有對應的預編譯版本或編譯工具。
