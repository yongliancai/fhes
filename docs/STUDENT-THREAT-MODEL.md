# v6.2 學生系統威脅模型

範圍：`server/`（最小 Node API）、`student.html`（學生頁面）、教師端的發布與帳號管理（`src/ui/student-admin-ui.js`）。日期 2026-11-25。方法：資產 → 攻擊者 → 威脅（STRIDE）→ 對策 → 驗證方式。

## 資產
1. 學生個人資料：姓名、座號、分數、作業狀態（未成年人資料，最高敏感）。
2. 學生帳號密碼（雜湊）與 Session。
3. 教師身分與班級管理權。
4. 照顧紀錄與小組獎勵的公平性。
5. 教師的 Google 試算表與 OAuth token（v6.1 資產，**不能**經過後端）。

## 攻擊者
- A1 好奇或惡作劇的學生（同班、他班），有自己的帳號，會改網址、用開發者工具、重送請求。
- A2 拿到別人密碼或共用裝置上殘留 Session 的人。
- A3 網路上的匿名攻擊者（猜密碼、掃描、CSRF、XSS）。
- A4 另一位老師（有合法教師帳號，但不屬於這個班）。
- A6 任何擁有 Google 帳號的人（Client ID 是公開的）：沒有在 `FHES_TEACHER_ALLOW` 名單上就不能成為老師。
- A5 伺服器資料外洩（備份檔、資料庫檔被拿走）。

## 剩餘風險（接受或待處理）
- **Argon2 沒有全域並行上限**：大量不同帳號名稱的登入請求會在執行緒池排隊（每個 IP 15 分鐘最多 200 次）。正式環境可在 nginx 加 `limit_req`。
- **教師 Bearer 在重新整理後仍有效到 8 小時**：頁面重新載入後前端拿不到 token（只在記憶體），但伺服器端的工作階段要等到期或按「登出」才失效。
- **學生把密碼告訴別人**：系統無法防止；教師可隨時重設。
- **教師帳號被盜**：沿用 Google 帳號安全；後端無法分辨。
- **SQLite 單機**：只適合一所學校的規模（數百名學生）；超過需換資料庫。
- **未在正式 VPS 驗證**：TLS、反向代理、真實 IP（`X-Forwarded-For` 信任設定）、備份都還沒做（需批准）。
- **Argon2 原生模組**：需在 VPS 上有對應的預編譯版本或編譯工具。
- **小老師判斷錯誤**：小老師按錯會讓同學在老師收取後開始計時；老師要偶爾看作業歷程。這是使用者選擇的設計（ADR-021、ADR-022）。
- **自動愛心只在教師端電腦開著時建立**：關機期間不會加，下次開啟時一次補上（依規則計算，不會多也不會少）。
