# FHES v6.2 圖鑑美術持續生成與安全提交作業手冊

本手冊供 Google Antigravity 定期排程（`/automation`）與人工續跑共同遵循，工作樹固定隔離在專用目錄 `fhes-v6.2-art`（分支 `feat/v6.2-art`），絕不與 `feat/v6.2-student` 或主工作目錄共用。

## 1. 首批 24 個素材位置（依 `src/data/catalog.js` 真實順序）

1. **六世界背景板（6 位，最優先）**：`bg-land`、`bg-ocean`、`bg-sky`、`bg-tech`、`bg-prehistoric`、`bg-fantasy`
2. **各世界前 3 種物種成年版（18 位，採六世界 round-robin）**：
   - 第 1 輪：`land-01` 貓咪（**已核准沿用**）、`ocean-01` 小丑魚、`sky-01` 麻雀、`tech-01` 巡邏機器狗、`prehistoric-01` 三葉蟲、`fantasy-01` 苔蘚精靈
   - 第 2 輪：`land-02` 狗狗、`ocean-02` 海星、`sky-02` 燕子、`tech-02` 清潔機器貓、`prehistoric-02` 菊石、`fantasy-02` 小飛龍
   - 第 3 輪：`land-03` 水豚、`ocean-03` 寄居蟹、`sky-03` 白鷺鷥、`tech-03` 自走車、`prehistoric-03` 劍龍、`fantasy-03` 月光兔

> `ocean-07_adult`（海龜）與 `tech-10_adult`（智慧探勘機）已核准並作為風格基準圖，但不在首批 24 位內，不計入首批完工數。首批起始狀態：1 approved / 0 review_pending / 23 fallback。

## 2. 嚴格邊界

- **不改正式清單**：機器 QC 通過的圖片僅輸出至 `assets/candidates/*.webp` 並登錄 `art/candidates.json`（狀態 `review_pending`）；**嚴禁自動寫入 `art/approved.json`、`assets/creatures/` 或 `src/data/art-manifest.js`**。
- **SVG fallback 不中斷**：未核准或未完成的圖位由 `src/art/sprites.js` 與 `src/ui/zoo.js` 自動回退 SVG，零破圖。
- **配額紀律**：每輪上限 6 張、禁止並行生圖；遇 HTTP 429 / `RESOURCE_EXHAUSTED` 立刻停止本輪並寫入 `art/raw/pipeline-state.json`；禁止切換帳號或無上限重試。
- **Git 邊界**：僅允許 commit 與 push 至 `feat/v6.2-art` 及更新對應 Draft PR；禁止 merge `main`、force push 或部署。
- **隱私與授權**：`art/raw/` 維持 gitignore，不推送大型原檔或本機使用者路徑；`docs/ASSET-LICENSES.md` 維持 AI 素材「尚未核准公開使用」直到人工完成授權與 IP 審查。
- **場景 QA 註記**：史前世界滄龍（`prehistoric-09`）水域缺失列為場景 QA，不自動改動 `src/data/catalog.js`。

## 3. 每輪 8 步標準流程

1. 執行 `node scripts/art-pipeline.mjs next --budget 6`（含排他鎖與 hash 對帳）；若回傳 `stopped: true` 立刻結束並回報。
2. 確認風格基準圖存在（`art/raw/land-01_adult.png`、`ocean-07_adult.png`、`tech-10_adult.png`）；背景板與成年角色附上 3 張風格基準與任務書指定前綴，提示詞一字不改取自 `art/prompts/prompts.json`。
3. 逐張生成候選圖（遇 429 立刻停輪並保存 checkpoint），原尺寸轉存 PNG 至 `art/raw/<key>.png`，更新 `art/raw/generation-log.csv` 與 `art/raw/pipeline-state.json`。
4. 逐張執行 `python scripts/art-qc.py <key>` 進行技術 QA 並產出候選 WebP 至 `assets/candidates/<key>.webp`，同時檢視圖片以標註語意／風格／IP 人工審核項。
5. 技術 QA 通過者寫入 `art/candidates.json`（`review_pending`），並更新 `docs/ART-QA-REPORT.md`（僅使用專案相對路徑）。
6. 執行 `npm run verify`（以及可用的 E2E fallback 測試）確認無迴歸。
7. 以白名單檢查 `git status` / `git diff`（不得改動 `art/approved.json`、`src/data/art-manifest.js`、`src/`、`index.html`，不得含憑證或本機路徑）。
8. 僅在有新候選產出且檢查全過時，commit 並 `git push origin feat/v6.2-art`；若本機已安裝並登入 `gh` CLI，建立或更新 Draft PR，否則標記 Draft PR 為 `BLOCKED (gh CLI 未安裝)` 並結束本輪。
