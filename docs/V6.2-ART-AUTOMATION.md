# FHES v6.2 圖鑑美術持續生成與安全提交作業手冊

本手冊供 Google Antigravity 定期排程（`/automation`）與人工續跑共同遵循，工作樹固定隔離在專用目錄 `fhes-v6.2-art`（分支 `feat/v6.2-art`），絕不與 `feat/v6.2-student` 或主工作目錄共用。

## 1. 首批 24 個素材位置（依 `src/data/catalog.js` 真實順序）

1. **六世界背景板（6 位，最優先，以 `16:9` 生成）**：`bg-land`、`bg-ocean`、`bg-sky`、`bg-tech`、`bg-prehistoric`、`bg-fantasy`
2. **各世界前 3 種物種成年版（18 位，以 `1:1` 採六世界 round-robin 生成）**：
   - 第 1 輪：`land-01` 貓咪（**已核准沿用**）、`ocean-01` 小丑魚、`sky-01` 麻雀、`tech-01` 巡邏機器狗、`prehistoric-01` 三葉蟲、`fantasy-01` 苔蘚精靈
   - 第 2 輪：`land-02` 狗狗、`ocean-02` 海星、`sky-02` 燕子、`tech-02` 清潔機器貓、`prehistoric-02` 菊石、`fantasy-02` 小飛龍
   - 第 3 輪：`land-03` 水豚、`ocean-03` 寄居蟹、`sky-03` 白鷺鷥、`tech-03` 自走車、`prehistoric-03` 劍龍、`fantasy-03` 月光兔

> `ocean-07_adult`（海龜）與 `tech-10_adult`（智慧探勘機）已核准並作為風格基準圖，但不在首批 24 位內，不計入首批完工數。首批起始狀態：1 approved / 0 review_pending / 23 fallback。

## 2. 嚴格邊界

- **不改正式清單**：機器 QC 通過的圖片僅輸出至 `assets/candidates/*.webp` 並登錄 `art/candidates.json`（狀態 `review_pending`）；**嚴禁自動寫入 `art/approved.json`、`assets/creatures/` 或 `src/data/art-manifest.js`**。
- **SVG fallback 不中斷**：未核准或未完成的圖位由 `src/art/sprites.js` 與 `src/ui/zoo.js` 自動回退 SVG，零破圖。
- **配額與容錯紀律**：每輪上限 6 張、禁止並行生圖；遇 HTTP 429 / `RESOURCE_EXHAUSTED` 立刻停輪並透過 `record` 保存 checkpoint；遇 HTTP 503 僅允許 1 次有界重試，仍失敗就保存進度停輪；禁止切換帳號或無上限重試。
- **Git 邊界**：僅允許 commit 與 push 至 `feat/v6.2-art` 及更新既有同一個 Draft PR；禁止 merge `main`、force push 或部署。
- **隱私與授權**：`art/raw/` 維持 gitignore，不推送大型原檔或本機使用者路徑；`docs/ASSET-LICENSES.md` 維持 AI 素材「尚未核准公開使用」直到人工完成授權與 IP 審查。
- **場景 QA 註記**：史前世界滄龍（`prehistoric-09`）水域缺失列為場景 QA，不自動改動 `src/data/catalog.js`。

## 3. 每輪 8 步標準流程（僅使用核准 CLI）

1. 先檢查既有紀錄並執行 `node scripts/art-pipeline.mjs next --budget 6`（含排他鎖、SHA-256 對帳與 429 冷卻檢查）；若回傳 `stopped: true` 立刻結束並回報。
2. 確認 3 張風格基準圖存在（`art/raw/land-01_adult.png`、`ocean-07_adult.png`、`tech-10_adult.png`）；依序生成（背景 `16:9`、角色 `1:1`），附上對應參考圖與規定前綴，提示詞一字不改取自 `art/prompts/prompts.json`。
3. 遇 429 立刻呼叫 `node scripts/art-pipeline.mjs record --key <key> --status pending --failure-kind RESOURCE_EXHAUSTED --retry-after <iso> --error "<msg>"` 並停輪；遇 503 最多 1 次有界重試，仍失敗則記錄 `--failure-kind HTTP_503_UNAVAILABLE` 並停輪。
4. 每張生圖完成後，執行 `python scripts/art-qc.py <key> --from-jpg <saved_jpg_path>`，原子轉存無損 PNG 至 `art/raw/<key>.png` 並做技術 QA 與候選 WebP 後製至 `assets/candidates/<key>.webp`（不通過會自動清除失敗 WebP）。背景板必須同時視覺檢視原 16:9 與裁切後 20:9 圖檔，確認角色活動區與重要構圖未被裁切；角色須檢視物種、肢體、朝向、風格與 IP 風險。
5. 通過者執行 `node scripts/art-pipeline.mjs record --key <key> --status review_pending --attempt <n> --model gemini-3.1-flash-image --promote-candidate`（原子更新 `pipeline-state.json`、`generation-log.csv` 與 `art/candidates.json`，絕不重複寫行、絕不改 `art/approved.json`），並更新 `docs/ART-QA-REPORT.md`（僅使用專案相對路徑）。
6. 執行 `npm run verify` 與 `node scripts/art-pipeline.mjs check-diff`；**任一項失敗即禁止 commit 與 push**。
7. 僅在有新候選產出且第 6 步全過時，commit 並 `git push origin feat/v6.2-art`；若本機已安裝登入 `gh` CLI，先查 `feat/v6.2-art` 既有 PR 並更新同一個 Draft PR（不重複建立），否則標記 Draft PR 為 `BLOCKED`。
8. 輸出本輪摘要（成功數量、候審數量、失敗原因、剩餘素材）並結束本輪。
