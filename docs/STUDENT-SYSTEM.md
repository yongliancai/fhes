# v6.2 學生系統：架構、權限與資料流

狀態：P0 設計（2026-11-25），分支 `feat/v6.2-student`。對應決策 ADR-015～ADR-020（`docs/DECISIONS.md`），威脅模型見 `docs/STUDENT-THREAT-MODEL.md`，API 合約見 `docs/api/openapi.yaml`。

> 來源文件：《FHES v6.2 Claude Code 分階段開發指令》（使用者提供）。《FHES v6.2 正式更新計劃書》**沒有收到**，以下依開發指令與使用者 2026-11-25 的需求說明設計；計劃書提供後需要對照一次（見「待確認」）。

## 1. 目標與不做的事

| 做 | 不做 |
|---|---|
| 教師發放個別學生帳號、密碼；學生登入由**後端**驗證 | 學生自行註冊、用 Google 帳號登入（國小學生多數沒有自己的帳號） |
| 學生看自己的分數、作業，以及所屬小組的園區與動物 | 學生看全班排行、其他同學的分數或作業、老師管理功能 |
| 小組共同照顧（餵食、陪伴），照顧值只影響心情、動畫、裝飾 | 照顧影響 XP、分數、收藏或成長階段；死亡、生病、懲罰、連續登入壓力 |
| 教師把「每生最小資料」發布到後端 | 把整份 Google 試算表、教師 token 或全班原始資料送到後端 |
| 本機與測試環境的 Node.js 後端 | 正式 VPS、正式資料庫、網域、PM2/nginx/CloudPanel 設定、部署（需另外批准） |

## 2. 架構

```
 教師（GitHub Pages：index.html，既有 v6.1）                     學生（VPS 上的同源頁面：student.html）
 ┌─────────────────────────────────┐                     ┌──────────────────────────────┐
 │ IndexedDB（本機正本）、Google 試算表 │                     │ 只有 HttpOnly Cookie，        │
 │ v6.1 純函式算出分數／作業／XP／收藏  │                     │ 不存任何資料在瀏覽器           │
 │ buildClassProjection() → 每生 DTO   │                     └──────────────┬───────────────┘
 └──────────────┬──────────────────┘                                    │ 同源 + Cookie + CSRF 標頭
                │ HTTPS + Bearer（記憶體內的教師工作階段）                     │
                ▼                                                        ▼
        ┌────────────────────────── 最小 Node.js API（server/）──────────────────────────┐
        │ Fastify 5 · better-sqlite3（單檔 SQLite）· Argon2id                              │
        │ 教師：Google ID token 在後端驗證 → 短期 Bearer；只能管理自己建立的班級              │
        │ 學生：帳號＋密碼 → 伺服器 Session（只存雜湊）；ACL 一律由 Session 推得               │
        │ 表：teachers, classes, student_accounts, sessions, student_projections,          │
        │     group_projections, group_care_events, audit_events, rate_limits, used_id_tokens│
        └────────────────────────────────────────────────────────────────────────────────┘
```

- **教師端仍是正本**：分數、作業、XP、收藏的規則與資料都留在 v6.1（IndexedDB＋試算表）。後端只收到**投影**（每位學生看得到的最小資料），不重算、不修改。
- **照顧資料是後端正本**：`group_care_events` 只存在後端，由後端裁決是否計入，教師端可讀取彙總。照顧值**不會**回寫 XP、分數或收藏。
- **學生頁面與 API 同源**（建議 VPS 子網域，例如 `https://fhes.<學校網域>/`）：Cookie 用 `__Host-` 前綴、`SameSite=Strict`，不需要跨站 Cookie（Safari 會擋）。
- **教師頁面跨來源**（GitHub Pages → VPS API）：用 Bearer token（只在記憶體），CORS 只允許設定的教師來源；不用 Cookie，所以沒有 CSRF 問題。

## 3. 身分與 Session

| | 教師 | 學生 |
|---|---|---|
| 證明身分 | Google ID token（v6.1 登入時取得），**後端**用 Google JWKS 驗簽、iss、aud、exp、iat（10 分鐘內簽發）、nonce；同一 token 只能換一次 | 教師發放的隨機帳號＋密碼（Argon2id），首次登入必須改密碼 |
| 帳號主鍵 | `SHA-256(iss｜sub)`，不存 email | 伺服器產生的隨機 ID；帳號名稱另外隨機產生 |
| 工作階段 | 不透明 Bearer，8 小時，只在記憶體；登出或重新載入即失效 | 不透明 Cookie `__Host-fhes_sid`（HttpOnly、Secure、SameSite=Strict、Path=/），閒置 2 小時、最長 12 小時 |
| 伺服器存的 | token 的 SHA-256 | session id 的 SHA-256 與 CSRF token |
| 註銷 | 登出；後端可列入撤銷 | 登出、改密碼、教師重設／停用 → 該生全部 Session 失效 |
| 防猜測 | Google 負責 | 帳號 5 次失敗後鎖定（1→2→4…最多 15 分鐘）；IP 15 分鐘 30 次失敗 → 429；不存在的帳號也做一次假驗證（時間一致） |

## 4. 權限矩陣

✅ 允許　❌ 拒絕（括號內為回應碼）

| 動作 | 未登入 | 學生（需改密碼） | 學生 | 同組同學 | 他組／他班學生 | 本班教師 | 他班教師 |
|---|---|---|---|---|---|---|---|
| 學生登入 | ✅ | — | — | — | — | — | — |
| 改自己的密碼 | ❌401 | ✅ | ✅ | — | — | — | — |
| 讀自己的分數、作業 | ❌401 | ❌403 | ✅ | — | ❌（無法指定別人；ID 由 Session 推得） | — | — |
| 讀所屬小組園區 | ❌401 | ❌403 | ✅ | ✅ | ❌（同上） | — | — |
| 餵食／陪伴所屬小組動物 | ❌401 | ❌403 | ✅（每日 3 次有效） | ✅ | ❌404（動物不在自己小組） | — | — |
| 建立／重設／停用學生帳號 | ❌401 | ❌401 | ❌401 | ❌401 | ❌401 | ✅ | ❌404 |
| 發布投影 | ❌401 | ❌401 | ❌401 | ❌401 | ❌401 | ✅ | ❌404 |
| 讀照顧彙總 | ❌401 | ❌401 | ❌401 | ❌401 | ❌401 | ✅ | ❌404 |

- 他班教師一律回 **404**（不透露班級是否存在）。學生 API **沒有**任何接受 `studentId`、`classId`、`groupId` 的參數；請求內帶這些欄位會被拒絕（400）。
- 教師的班級以「教師＋本機班級 ID」綁定，換了 Google 帳號就是另一位教師，看不到原本的班級。

## 5. 資料流

1. **建立班級連結**：教師端呼叫 `POST /api/teacher/classes`（本機班級 ID、班級名稱）→ 取得 `classKey`。
2. **發放帳號**：勾選學生 → 後端產生帳號與初始密碼，**只回傳一次**；教師列印或抄寫後發給學生。後端只存 Argon2id 雜湊。
3. **發布資料**：教師按「發布到學生系統」→ 前端用 v6.1 純函式算出每生 DTO（`src/core/student-projection.js`）→ `PUT /api/teacher/classes/{classKey}/projection`，帶 `version`（遞增）與內容 `hash`。
   - 版本較舊 → 409（不覆蓋）；同版本同內容 → 200（冪等）；同版本不同內容 → 409。
   - 新版本**整班替換**：沒出現在新投影裡的學生或小組，舊資料會刪掉（避免幽靈資料）。
4. **學生登入 → 看資料**：學生頁面只拿到自己的 DTO 和小組 DTO。超過 3 天沒更新時顯示「老師上次更新：…」。
5. **照顧**：`POST /api/student/care`（動物、動作、`idempotencyKey`）→ 後端在一個交易內檢查身分、小組、動物、當日次數 → 計入或只播動畫。

## 6. 學生看得到的資料（DTO）

學生本人：
- 姓名（教師可選擇只顯示座號）、座號、小組。
- 可用分數、累計獲得分數。**不含愛心（扣分提醒）**：維持 v6.1「不公開個人負面紀錄」的精神，學生系統也不放負向紀錄。
- 作業：最近 60 天、未封存的作業，各自的**繳交**（未登記／未交／已交／免交）與**訂正**（未批改／待訂正／已訂正／不需訂正）分開顯示；`unchecked ≠ missing`、`submitted ≠ done`。

所屬小組：
- 小組名稱、小組 XP、世界、動物（收藏 ID、成長階段、是否特殊收藏）。
- 照顧彙總（後端計算）：每隻動物的照顧值與心情、小組徽章、今天參與人數（只有人數，沒有名單）。

不給：其他同學的姓名、分數、作業、愛心、全班排行、教師 token、試算表 ID。

## 7. 照顧與獎勵規則（ADR-019）

- 每位學生每天（Asia/Taipei）最多 **3 次有效照顧**，跨小組合計（換組不會重置）。超過只播動畫，回應 `counted: false`。
- 同一個 `idempotencyKey` 重送只算一次（資料庫唯一鍵）；有效次數用 `slot 1..3` 唯一鍵保證，即使同時送 100 次也不會超過 3。
- 動物必須在學生**目前**小組的有效收藏中（被撤銷就不能照顧）；帳號停用、需改密碼時不能照顧。
- 效果只有正向：
  - **心情**：最近 3 天的照顧次數 → 平靜 → 開心 → 超開心（沒有難過或生病）。
  - **小組照顧徽章**：累計有效照顧 10／30／60／100／160 次解鎖園區裝飾（花圃、彩旗、野餐墊、燈串、小舞台）。
  - **團隊日**：某天有一半以上（無條件進位）的組員照顧過 → 小組得到一顆團隊星。鼓勵大家都參與，而不是少數人刷次數。
- **公平**：上限讓有自己裝置的學生無法壓過別人；團隊星看「參與人數」不看次數。沒有個人裝置的學生可以在教室共用裝置登入（登出後換人）。
- **不碰既有規則**：照顧不產生 XP、分數或收藏，也不改成長階段（成長仍只看 XP）。

## 8. 部署形態（建議，未執行）

- VPS 上新增一個獨立的 Node 程序（例如 `127.0.0.1:8790`），由現有 nginx 反向代理到新的子網域；不改動既有站台。
- SQLite 單檔放在專用目錄，每日備份（檔案複製＋保留 30 天），備份檔加密存放。
- 需要使用者批准的事項見 ADR-020 與 `docs/STUDENT-DEPLOY-TODO.md`（P6 產出）。
