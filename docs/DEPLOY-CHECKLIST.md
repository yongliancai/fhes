# 合併／部署前檢查清單與還原指引

> 本清單只是準備。**合併 `main`、發布 GitHub Pages、使用真實學生資料、連接真實 Google 帳號，都需要使用者另外明確批准。** 截至 Draft PR，以上都沒有執行。

## A. 合併前（使用者批准後才做）
- [ ] Draft PR #1 的 CI（`verify` + `e2e`）在最新 commit 為綠燈。
- [ ] 本機 `npm ci && npm run verify && npm run test:e2e` 通過（附日誌）。
- [ ] 人工試用一輪（建議用合成資料）：加分／扣分／消除／兌換、秩序記錄→待確認、作業登記與投影模式、圖鑑解鎖、備份匯出→載入。
- [ ] 確認陸地以外的圖鑑名單、稀有度、知識卡文字可以接受（目前為專家建議）。
- [ ] 確認佔位美術可以先上線，或等正式插畫（見 `docs/ASSET-LICENSES.md`）。

## B. 發布前（GitHub Pages）
- [ ] 確認 Pages 的發布來源（branch / folder）與網址；v6 需要整個 repo 的 `index.html` + `src/` 一起發布。
- [ ] 老師先在 v5.1 匯出一份 JSON 備份（升級前保險）。
- [ ] 若要用雲端同步：依 `docs/GOOGLE-SHEETS-SETUP.md` 建立 OAuth Client ID，「已授權的 JavaScript 來源」加入正式網址的來源（例：`https://yongliancai.github.io`）。
- [ ] 確認學校對「學生資料存放在個人／學校 Google 帳號」的規定。
- [ ] 發布後開啟正式網址：左下角應顯示 `v6.0`；F12 主控台沒有錯誤。

## C. 真實 Google 整合驗收（BLOCKED：需要使用者提供／授權）
- [ ] 使用者提供 OAuth Client ID（公開識別碼）與允許的來源。
- [ ] 使用者核准用**測試用試算表＋合成資料**做一次真實連線測試：連接、建立試算表、兩台電腦同步、授權過期後重新連線、衝突處理。
- [ ] 通過後才考慮放真實班級資料。

## D. 還原（rollback）
1. **程式還原**：GitHub Pages 改回發布 v5.1（`main` 的 `44879bb`），或在合併後 `git revert` 合併 commit。不需要動任何資料。
2. **資料還原**：
   - v6 升級只「新增」資料表，原本 v5.1 的資料表與欄位不變；但 v5.1 程式無法開啟已升級到第 2 版的瀏覽器資料庫，也拒讀 v6 備份。
   - 回到 v5.1 前：在 v6 總覽按「⬇ v5.1 相容備份」（含升級後的加扣分、愛心、歷史；不含作業、XP、圖鑑），再到 v5.1 用無痕視窗或清除該網站資料後「載入備份」。同時保留一份 v6 完整備份，日後再升級可以載回。
   - Google 試算表中的資料不會因還原程式而消失；刪除的資料以墓碑列保留（`deleted=1`，資料欄仍在）。
3. **舊 Firebase**：本專案從未讀取、修改或刪除 Firestore 資料；還原到 v5.1 後原本的 Firebase 同步照舊可用。

## E. 已知限制（上線前需知悉）
- Google OAuth／Sheets 只在模擬環境驗證（真實帳號測試 BLOCKED）。
- 瀏覽器 token 約 1 小時過期，需要老師點「重新連線」（無背景長效權杖，這是刻意的安全設計）。
- Google 試算表無交易機制：設計給「一位老師、多台裝置」，衝突交由老師處理，不保證強一致。
- v6 需經由網址（http/https）開啟，直接開啟本機 HTML 檔無法運作。
- 圖鑑美術為原創佔位圖；陸地以外的角色為專家建議名單。
